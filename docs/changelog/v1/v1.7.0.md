# vitest-runner v1.7.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

A test that kills by a computed pid can reach every process the user owns. This release adds an opt-in way to run the whole suite in its own PID namespace, where a kill can only reach the run's own processes.

It also changes how leftover scratch roots from crashed runs are found. The sweeper used to trust the pid in a root's name. Inside a PID namespace every other run's pid looks dead, so it would have deleted live runs' scratch. Each run now holds a liveness socket in its root instead, through the new runtime dependency [`@cldmv/lib-process`](https://github.com/CLDMV/lib-process).

Isolation is off by default, and nothing else about how a run behaves changes.

---

## ✨ Features

### Run the suite in its own PID namespace ([#130](https://github.com/CLDMV/vitest-runner/pull/130))

- New `isolate` option, `--isolate` flag and `CLDMV_TEST_ISOLATE=1` environment variable. When it's on, the runner re-runs its own command line under `unshare -U --map-current-user -p -f --mount-proc` and returns that run's exit code. SIGINT and SIGTERM are passed on, and when the run ends the kernel kills anything it left in the namespace.
- If the process is already in a PID namespace (a container, a k3s pod, an earlier `unshare -p`), it runs as is. The check compares `/proc/self/ns/pid` with the kernel's initial namespace.
- When unprivileged user and PID namespaces aren't available, the run fails before it starts, with `unshare`'s own message. It never falls back to running unsandboxed.
- The user id stays the same inside (`--map-current-user`, not `-r`, which breaks `cp -a`). The network isn't separated.
- Linux only, and it can't be combined with `json`. Code in your script before `run()` runs twice, once outside and once inside.

### Scratch roots are swept by liveness, not by pid ([#130](https://github.com/CLDMV/vitest-runner/pull/130))

- Run roots are named with 16 random hex characters instead of `<pid>-<timestamp>`.
- Each run holds an `alive` socket from `@cldmv/lib-process` in its root. The next run's sweep removes a root whose socket refuses connections straight away, whatever namespace either run is in.
- A root with no socket (a run still starting, or a path too long for a Unix socket) is only removed after 10 minutes without an update. Live runs touch their root every minute.
- Roots named the old way are removed after a day.

## Upgrade notes

- No breaking changes. Isolation is off unless you turn it on.
- Scratch roots left by v1.6.x or earlier are cleaned up after a day instead of right away.
- `isPidAlive` is gone from the internal `src/core/scratch.mjs`. It was never exported from the package.
