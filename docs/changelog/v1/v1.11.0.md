# vitest-runner v1.11.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

The coverage index from [v1.10.0](./v1.10.0.md) was only written when the runner merged the coverage blobs itself. A suite that runs with `mergeReports: false` and merges with its own `runMergeReports` call got no index, and nothing exported could write one. Some suites merge externally only to give the merge more heap than each test file gets.

This release covers both cases. The merge can have its own heap limit, so those suites can go back to the runner's merge. A suite that still merges itself can write the index with a new exported function.

---

## ✨ Features

### Merge-only heap limit ([#155](https://github.com/CLDMV/vitest-runner/pull/155))

- `mergeMaxOldSpaceMb`, `--merge-heap-mb <mb>` or `VITEST_MERGE_HEAP_MB` sets `--max-old-space-size` for the coverage merge alone: the final `vitest --mergeReports` and each batch process. It falls back to `maxOldSpaceMb` / `VITEST_HEAP_MB`, so nothing changes unless it's set. Per-file heaps are unaffected.
- Text output prints `Merge heap limit: <n> MB` when it differs from the per-file limit.

### Coverage index after an external merge ([#155](https://github.com/CLDMV/vitest-runner/pull/155))

- `writeCoverageIndexFromBlobs({ blobsDir, cwd, outputDir, vitestBin, commit })` is exported from the package root. Call it after your own merge and before the blobs are deleted.
- `blobsDir` takes one directory or several, for example a node and a browser blob set. Only the files directly inside each directory are read.
- Each blob's test files are read from the blob itself, so no mapping from blob to test file is needed. A blob that holds several test files credits each of them.
- `outputDir` defaults to `<cwd>/coverage`. `vitestBin` defaults to the vitest installed for `cwd`. `COVERAGE_INDEX_FILENAME` is exported as well.

Resolves [#154](https://github.com/CLDMV/vitest-runner/issues/154).

## Upgrade notes

- No breaking changes. The JSON report's `coverageIndex.testFiles` now counts distinct test files rather than blobs read; for the runner's own merge, which writes one blob per test file, the number is the same.
