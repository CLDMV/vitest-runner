# vitest-runner v1.8.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

v1.7.0's isolation skips itself when the runner is already in a PID namespace, which is right for normal use but means the isolated path can't be tested in a container or k3s pod. This release adds a forced mode that re-runs under `unshare` anyway. It also adds the one test v1.7.0 was missing for full function coverage.

Nothing changes unless you ask for the forced mode.

---

## ✨ Features

### Forced isolation ([#135](https://github.com/CLDMV/vitest-runner/pull/135))

- `isolate: "force"`, `--isolate=force` or `CLDMV_TEST_ISOLATE=force` re-run the suite in a new PID namespace even when the runner is already in one. `true` / `--isolate` / `CLDMV_TEST_ISOLATE=1` keep skipping there, as before.
- The same rule applies as for plain isolation: if `unshare` isn't permitted, the run fails before it starts and never runs unsandboxed.
- The re-run process gets `VITEST_RUNNER_ISOLATED=1`. The runner removes it from its environment on its first `run()` call, so it doesn't re-run itself again and the test processes it starts don't inherit it. A test that runs the runner again with `force` still gets its own nested namespace.

---

## 🧪 Tests

- Covers `release()` in `createRunScratchRoot` when closing the liveness socket fails, which brings function coverage back to 100% ([#133](https://github.com/CLDMV/vitest-runner/pull/133)).
- A real-`unshare` integration test for the forced mode. It runs wherever unprivileged `unshare` works, namespaced or not, and is skipped elsewhere ([#135](https://github.com/CLDMV/vitest-runner/pull/135)).
