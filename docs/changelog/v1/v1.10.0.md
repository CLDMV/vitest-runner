# vitest-runner v1.10.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

A coverage run already writes one blob per test file, and until now the runner threw them away after the merge. Before deleting them it now writes `coverage-index.json` next to the coverage reports: for each source file, every function and the test files that executed it. With that index a repo can re-measure one source file by running only the tests that reach it, instead of the whole suite.

The index is on by default whenever the runner merges the coverage reports. It doesn't change the run's result: if it can't be written, the runner prints a warning and carries on.

---

## ✨ Features

### Coverage index ([#150](https://github.com/CLDMV/vitest-runner/pull/150))

- After the merge, and before the blobs are removed, the runner writes `<reportsDirectory>/coverage-index.json` (`coverage/` by default, or `--coverage.reportsDirectory=<dir>`). The layout is `{ version, commit, files }`, with `files` mapping each source file to `{ <function>: [<test files>] }`.
- A function lists a test file when its call count in that file's blob is above zero. Only functions in the coverage map are indexed, never module top-level code, which every test that loads the package would otherwise reach. Every function appears, with `[]` when no test reached it. A name used more than once in a file is keyed `name@<line>` for each occurrence.
- Paths are relative to `cwd` with forward slashes, so the index matches between CI and a local checkout. `commit` is `git rev-parse HEAD`, else `GITHUB_SHA`, else `null`.
- The blobs are read one at a time, so the memory cost stays at one blob.
- The JSON report has a new `coverageIndex` field: `{ path, files, testFiles }`, or `null` when no index was written.
- `coverageIndex: false` or `--no-coverage-index` turns it off. Nothing is written with `mergeReports: false` / `--no-merge-reports`.

Resolves [#148](https://github.com/CLDMV/vitest-runner/issues/148).
