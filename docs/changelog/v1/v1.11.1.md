# vitest-runner v1.11.1 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `next` → `master`

---

## Overview

The per-file idle limit from [v1.9.0](./v1.9.0.md) killed long files in coverage runs while their tests were passing. Coverage runs use the default and blob reporters, and with stdout not a TTY the default reporter prints nothing until a file ends. So a file that ran longer than the idle limit (10 minutes by default) looked silent and was failed with only its `RUN` header in the output. Runs without coverage weren't affected unless their reporters were just as quiet.

The build also stops bundling. `dist/` now mirrors `src/` one minified file per module, and the CLI moves from `bin/vitest-runner.mjs` to `dist/bin/vitest-runner.mjs`.

## 🐛 Bug Fixes

### Coverage runs report test progress to the idle watchdog ([#159](https://github.com/CLDMV/vitest-runner/pull/159))

- Each coverage child also loads a small heartbeat reporter. On reporter events (tests and hooks starting and finishing, console output, coverage) it writes to an extra pipe on file descriptor 3, at most once a second.
- The runner resets a file's idle timer on that pipe as well as on stdout and stderr. A file whose tests stop making progress still trips the limit, and the parsed output is unchanged.
- `runSingleFile({ heartbeat: true })` turns this on for direct callers. The reporter ships as `dist/core/heartbeat-reporter.mjs`, next to `dist/core/spawn.mjs`, which finds it by a relative URL.

Fixes [#158](https://github.com/CLDMV/vitest-runner/issues/158).

### The build ships one file per module instead of bundles ([#162](https://github.com/CLDMV/vitest-runner/pull/162))

- tsup built two bundles: `dist/index.mjs`, and `bin/vitest-runner.mjs` carrying its own copy of `core/` and `utils/`. Both helper processes shipped twice, because the inlined modules find them next to whichever bundle runs.
- `scripts/build.mjs` now runs esbuild with `bundle: false` over `src/**/*.mjs`. `dist/` mirrors `src/`, one minified file per module with names kept and source maps. `dist/index.cjs` is still copied verbatim from `src/index.cjs`.
- The CLI is `dist/bin/vitest-runner.mjs` (package.json `"bin"`) and imports `../index.mjs`. Each helper and the heartbeat reporter exist once, next to the module that starts them. The top-level `bin/` directory is no longer published.
- tsup is dropped and esbuild is a direct devDependency. `npm run test:dist` now runs the CLI tests against the built CLI and checks the layout.

Resolves [#160](https://github.com/CLDMV/vitest-runner/issues/160).

## Upgrade notes

- The `vitest-runner` command and the package entry points are unchanged. Anything that runs the CLI by its file path, `node_modules/@cldmv/vitest-runner/bin/vitest-runner.mjs`, must switch to `dist/bin/vitest-runner.mjs`, or better, call the `vitest-runner` command.
- Suites that set `fileIdleTimeoutMs: 0` (or `--file-idle-timeout 0`) for coverage runs to work around this can go back to the default limit. One test that legitimately runs silent for longer than the limit still needs a higher limit or a `perFileTimeoutOverrides` entry.
