# vitest-runner v1.5.0 Changelog

**Release Date**: September 2026
**Release Type**: Minor
**Branch**: `release/1.5.0`

---

## Overview

Discovery previously only skipped `node_modules` and hidden directories, so a substring pattern that doesn't resolve to a path fell back to walking the whole `testDir` — including scratch directories like `tmp/` that can hold git worktrees or staged fixtures carrying their own copy of the suite. Every copy then ran, against the wrong tree, and failed. This release adds an `exclude` option to keep discovery out of directories and files like that. No breaking changes.

---

## ✨ Features

### An `exclude` option for test discovery (#57, #58)

An `exclude` API option and repeatable `--exclude <glob>` CLI flag: directory/file globs, relative to `cwd`, that discovery never enters — for example `exclude: ["tmp/**", "dist/**"]` or `vitest-runner --exclude 'tmp/**' --exclude 'dist/**'`. Applies to both the default scan and the partial-path pattern-resolution fallback, so a workaround of resolving substring patterns against known suite roots before calling `run()` is no longer needed. The matcher supports a reduced glob subset (`*`, `**`, `?`) implemented directly in `src/core/discover.mjs`, keeping the package's zero-runtime-dependency footprint (`chalk` is still the only one).

---

## Upgrade notes

No breaking changes — drop-in for v1.4.4. `exclude` defaults to `[]` (no exclusions) on both the `run()` API and the CLI, so existing callers are unaffected until they opt in.
