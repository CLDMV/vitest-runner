# vitest-runner v1.11.4 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `next` → `master`

---

## Overview

vitest-runner now depends on `@cldmv/lib-process` 0.1.1, which frees a lock the moment `release()` returns, so a process that releases and then blocks no longer leaves the next process waiting until it times out. The rest is the fleet's new dev tools and the CLDMV/.github v4.47.0 Dependabot groups. vitest-runner's own behaviour and options are unchanged.

---

## 🔧 Dependencies

- **Runtime:** `@cldmv/lib-process` `^0.1.0` → `^0.1.1` ([#172](https://github.com/CLDMV/vitest-runner/pull/172)). v0.1.1 makes `lock().release()` and a holder's `close()` stop listening before they return, so the lock is free straight away even when the caller then blocks, for example on a `spawnSync` of the next process ([CLDMV/lib-process#6](https://github.com/CLDMV/lib-process/issues/6)).
- **Dev tooling:** `@cldmv/configs` 1.5.0 and `@cldmv/fix-headers` 2.6.1, with `npm update` for the rest of the dev toolchain ([#172](https://github.com/CLDMV/vitest-runner/pull/172)). vitest-runner keeps its own ESLint config, so the configs 1.5.0 lint changes don't apply to it.

## 🔧 CI & tooling

- `dependabot.yml` takes the npm groups from the CLDMV/.github v4.47.0 template, so the CLDMV dev tools arrive in one `cldmv-dev` PR and the generic patch and minor groups exclude every named family ([#172](https://github.com/CLDMV/vitest-runner/pull/172), [CLDMV/.github#593](https://github.com/CLDMV/.github/issues/593)).
