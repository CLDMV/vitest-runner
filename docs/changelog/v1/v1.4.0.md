# vitest-runner v1.4.0 Changelog

**Release Date**: September 2026
**Release Type**: Minor
**Branch**: `release/1.4.0`

---

## Overview

The headline of this release is a real, working build: the package now ships a bundled `dist/` (library) and `bin/` (CLI), and — separately — an npm packaging bug that had silently disabled the published CLI in **every prior release** is fixed. It also adds a runner-owned scratch-directory lifecycle for test files, fixes a display bug where the final summary attributed one file's test count to another when two files shared a basename, and rounds out the repo's own CI/release automation and file-header consistency.

**Compatibility.** No API changes. `main`, `module`, `types`, and the `bin` command all still resolve to the same public entry points; only what backs them changed (a real build instead of hand-written shims, and a corrected `bin` path).

## 🐛 Bug Fixes

### The published CLI has never actually worked (#26)

npm's `bin` field validation rejects a leading `./` and silently strips the entry on publish — `package.json` declared `"vitest-runner": "./bin/vitest-runner.mjs"`, so every npm install of every prior release (`npm warn publish "bin[vitest-runner]" script name bin/vitest-runner.mjs was invalid and removed`) shipped with no working `vitest-runner` command at all. Found while investigating why the v1.3.3 publish job failed. The fix is one character: drop the leading `./`.

### Final summary merged same-basename files from different directories (#13)

Vitest's own `vitest run <filter>` CLI matches any discovered test file whose path _contains_ the filter as a substring, not just an exact-path match. Two files sharing a basename and immediate parent directory at different depths — `tests/contract.test.vitest.mjs` and `packages/a/tests/contract.test.vitest.mjs`, a normal shape for a workspace/monorepo — collided: the shorter path is a trailing substring of the longer one, so the per-file run for the shorter path also swept in the longer one's file, inflating that file's test count and double-counting it in the run's grand totals and its "PASSED TEST FILES" summary row. Each file invocation now excludes every other discovered file whose path would spuriously match its own.

### Coverage-badge CI job had no real build to run (#4)

The coverage-badge job's `coverage_build_command` defaults to `npm run build` — this repo never had one, so a dummy no-op `build` script was standing in as a stopgap since the v4 onboarding. The coverage leg now runs the real `build:ci` (lint + format:check + types:build), which preserves `src/` for the coverage run to measure.

## ✨ Features

### A real build: `dist/` and `bin/` are bundled, not hand-written (#4)

The package shipped raw, hand-written `index.mjs`/`index.cjs` at the repo root — `index.cjs` was an async dynamic-import shim, and `src/` shipped alongside them regardless. [tsup](https://github.com/egoist/tsup) now bundles `src/runner.mjs` into `dist/index.mjs` + `dist/index.cjs` (the CJS build is generated from the same source instead of hand-maintained, and is a real synchronous `require()` instead of a Promise-wrapping shim), and bundles `src/bin/vitest-runner.mjs` into the published `bin/vitest-runner.mjs` (shebang preserved). `src/` is no longer shipped — `dist/` and `bin/` are complete, self-contained bundles. A `vitest-runner-dev` package.json export condition (matching `@cldmv/slothlet`'s `*-dev` convention) lets a workspace/local-checkout consumer resolve straight to `src/runner.mjs` instead of requiring a fresh build on every change.

Sourcemaps are generated during `npm run build` for local debugging but excluded from the published tarball; shipping them as an optional companion package (mirroring `@cldmv/slothlet-types`) is tracked as [#25](https://github.com/CLDMV/vitest-runner/issues/25) for later, once the package's surface area justifies the extra machinery.

### Runner-owned per-run scratch directory (#18)

Test suites previously created their own scratch directories (`mkdtemp`) with per-suite cleanup that was easy to get wrong — a real-world case leaked 6,048 directories from one missing `mkdtemp`-base cleanup. The runner now creates a per-run scratch root (`tmp/vitest-runner/<pid>-<timestamp>/` by default, configurable via `scratchDir`) before any file runs, with one subdirectory per file invocation exposed to that file's child process as `VITEST_RUNNER_TMP`. The root is removed on every exit path — normal completion, a thrown error, or SIGINT/SIGTERM — unless `keepTmp` is set, and stale roots left by a crashed prior run (dead PID) are swept at the start of the next run. Test files get a `makeRunTmpDir(label)` helper (exported from the package) for an `mkdtemp`-style subdirectory under `VITEST_RUNNER_TMP` instead of managing their own base. New CLI flags: `--keep-tmp`, `--scratch-dir <path>`.

## 🔧 CI & Tooling

### Completed the v4 staging-branch onboarding — 10 missing workflows + `dependabot.yml`

This repo was onboarded onto the CLDMV v4 flow with a partial workflow set (13 of the standard 22 files). The rest are now in place: `release-merge.yml` — the actual approval-triggered auto-squash-merge for the persistent `next→master` release PR (previously the PR's body auto-refreshed but nothing ever merged it, so every release needed a manual "Squash and merge" click); `dependency-review.yml` — the third GHAS-gated security workflow, alongside the already-present `codeql.yml` and `scorecard.yml`; `branch-retention.yml`, `cla.yml`, `dependabot-auto-merge.yml`, `labeler.yml`, `stale.yml`, `welcome.yml` for community/automation health; and `release-notify.yml` / `tag-health.yml` as release companions. `.github/dependabot.yml` was entirely missing — Dependabot had no configuration at all, so no automated dependency PRs were ever opening.

### Normalized every file header with `@cldmv/fix-headers`

Every `.github/workflows/*.yml` file copied from a CLDMV/.github template — including the ones added this release — carried the _template's_ own header (`@Project: @cldmv/.github`, `@Filename` pointing at the `examples/` path) instead of this repo's. `src/` and `tests/` source files had no headers at all. [`@cldmv/fix-headers`](https://github.com/CLDMV/fix-headers) is now wired in (`npm run fix:headers`, matching the wrapper convention already used in `@cldmv/uuid` and `@cldmv/slothlet`) and has normalized all of it — each file's original recorded author and creation date are preserved; only the project/path metadata and "last modified" stamp are corrected.
