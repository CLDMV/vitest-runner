# vitest-runner v1.4.1 Changelog

**Release Date**: September 2026
**Release Type**: Patch
**Branch**: `release/1.4.1`

---

## Overview

This release completes the vitest 4→5 major upgrade that v1.4.0's dependency-bump PRs had started but left unresolved, fixes the README's npm badges, and fixes a `prepack` bug that was silently crashing every publish job (npm and GitHub Packages both) since v1.4.0. No API changes.

---

## 🐛 Bug Fixes

### Bumping vitest to 5 alone broke `npm ci` (#31)

`@vitest/coverage-v8` peers `vitest` at an _exact_ version, not a range. Dependabot's grouped update bumped `vitest` to `5.0.1` but left `@vitest/coverage-v8` pinned to `4.1.9`, so `npm ci` failed with an ERESOLVE conflict on every affected branch. `@vitest/coverage-v8` is now bumped alongside `vitest` to `5.0.2`, and the `vitest`/`@vitest/*` Dependabot group in `.github/dependabot.yml` now covers this whole family together so future bumps can't split the same way again. Verified against the full 289-test suite and confirmed vitest 5's breaking changes (locator objects, inlined `expect`, removed entry points) don't touch the CLI flags this runner depends on (`--config`, `--exclude`, `--mergeReports`, `--coverage`).

A separate, narrower Dependabot PR bumping only the transitive `@vitest/mocker` to `5.0.2` (while `vitest` stayed at `4.1.9`) hit the identical conflict and was closed as superseded by this fix — `@vitest/mocker` now moves to a matching 5.x automatically as part of `vitest`'s own dependency tree.

### README npm badges referenced the unscoped package name (#37)

The npm version/downloads/last-update badge _images_ used the bare `vitest-runner` name instead of the scoped `@cldmv/vitest-runner`, so they rendered "package not found" on shields.io even though the link targets underneath them were already correct.

### `prepack` crashed every publish job since v1.4.0 (#40)

`package.json`'s `"prepack": "npm run build"` (added in v1.4.0 alongside the real `dist/`/`bin/` build) runs on every `npm publish`, including in CI's publish job — which runs against a bare, already-built `package-contents` artifact with no `node_modules` and no `tsup` binary. Every npm and GitHub Packages publish attempt since v1.4.0 failed identically with `sh: 1: tsup: not found`. `prepack` now checks whether `tsup` is actually resolvable (`node_modules/.bin/tsup`) before rebuilding: when it is (local dev, the build job), it always rebuilds from source, so a stale `dist/` is never a risk; when it isn't (the publish job's bare artifact directory, which has no lockfile to install from either), it trusts the already-built `dist/` that the build job just produced and packed.

This is a workaround for a gap in the CLDMV/.github reusable publish workflow itself — the generated publish command doesn't pass `--ignore-scripts` against that bare artifact directory, which is unsafe for any repo with a real build-dependent `prepack`. Filed upstream as [CLDMV/.github#320](https://github.com/CLDMV/.github/issues/320); tracked here as [#41](https://github.com/CLDMV/vitest-runner/issues/41) to drop this repo's guard once that ships.
