# vitest-runner v1.6.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

The `vitest-runner-dev` export condition now covers `require()` as well as `import`, so a checkout run with `--conditions=vitest-runner-dev` loads `src/` from both module systems. The repository's own tests run that way, so they exercise the source instead of the built `dist/`.

The other change is a requirement change: `engines.node` rises from `>=22.12.0` to `>=22.22.0`. The runner itself is unchanged. `src/index.mjs` is the same as in [v1.5.6](./v1.5.6.md), and in `src/index.cjs` only the error message for a Node.js without `require(esm)` changed, so that it names the new floor.

## ✨ Features

### `require` target on the `vitest-runner-dev` condition ([#110](https://github.com/CLDMV/vitest-runner/pull/110), fixes [#99](https://github.com/CLDMV/vitest-runner/issues/99))

The condition used to map only `types` and `import`, so `require("@cldmv/vitest-runner")` in a checkout always loaded `dist/index.cjs`, even with the condition set. It now maps `require` to `src/index.cjs` too:

| Run                                           | `import` loads   | `require()` loads |
| --------------------------------------------- | ---------------- | ----------------- |
| `node app.mjs`                                | `dist/index.mjs` | `dist/index.cjs`  |
| `node --conditions=vitest-runner-dev app.mjs` | `src/index.mjs`  | `src/index.cjs`   |

Published installs only contain `dist/`, so nothing changes for consumers.

The Vitest config passes the condition through `resolve.conditions`, `ssr.resolve.conditions` and `test.nodeOptions`, and `test:cjs` runs `node --conditions=vitest-runner-dev --test`. A new test checks that the condition sends both `require()` and `import` to `src/`, and that without it `require()` gets `dist/`.

## 📦 Requirements

### Node.js 22.22.0 or later is required ([#110](https://github.com/CLDMV/vitest-runner/pull/110))

`engines.node` rises from `>=22.12.0` to `>=22.22.0`. Node.js 22.12.x prints an `ExperimentalWarning` when `require()` loads the ES module build through the CommonJS entry, and the build and test toolchain needs a recent Node.js 22 (tsup 9 alone requires 22.18 or later), so older versions can no longer be tested. The floor is set at 22.22.0, and the CI and publish matrices start there.

On an older Node.js, npm prints an `EBADENGINE` warning on install, or refuses to install when `engine-strict` is set. The CommonJS entry's error for a Node.js without `require(esm)` now reads `require() needs Node.js >=22.22.0`.

## 🔒 Security & supply chain

- `overrides` now pin `katex` to `>=0.19.1 <1.0.0` (it was `>=0.18.2`) and add `minimatch` `^11.0.3`, which moves `minimatch` from 10.2.5 to 11.0.3 and clears advisories that reach the repository through `@eslint/markdown` and ESLint ([#112](https://github.com/CLDMV/vitest-runner/pull/112)). `katex` stays at 0.19.1; the new upper bound only keeps a future 1.x out. Both are development-only and neither ships with the package.

## 🔧 CI & tooling

- The `min_node_version` default in `ci.yml` and `publish.yml` moves from 22.12.0 to 22.22.0, matching `engines` ([#110](https://github.com/CLDMV/vitest-runner/pull/110)).

## Upgrade notes

- **Node.js 22.22.0 or later is now required** (it was 22.12.0). Upgrade Node.js before upgrading the runner, or stay on v1.5.6.
- The runner's options, behavior and exports are unchanged, so no code or config changes are needed.
- In a checkout, `--conditions=vitest-runner-dev` now also sends `require()` to `src/index.cjs`.
