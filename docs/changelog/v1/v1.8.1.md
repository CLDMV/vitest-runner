# vitest-runner v1.8.1 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `next` → `master`

---

## Overview

`vitest --mergeReports` reads every coverage blob into memory at once, and each blob carries a coverage map of the whole `include` set. A suite with hundreds of test files could pass every test and then run the final merge out of heap. This release merges the blobs in batches first, so the merge's memory no longer grows with the number of test files.

Suites with 50 blobs or fewer see no change.

---

## 🐛 Bug Fixes

### Coverage blobs are merged in bounded-memory batches ([#132](https://github.com/CLDMV/vitest-runner/pull/132))

- When there are more blobs than the batch size, the runner reduces them in rounds before the final merge. Each batch of up to 50 blobs is merged into one blob in its own Node process, reading one blob at a time, with `maxOldSpaceMb` / `VITEST_HEAP_MB` as its heap ceiling when set. Rounds repeat until 50 or fewer remain, then the usual `vitest --mergeReports` runs over the reduced set.
- Reporters, `coverage.thresholds`, test failures and the exit code behave exactly as with a single merge. Only Vitest's "Per blob" timing line lists the reduced blobs.
- The batch size is set with the `mergeBatchSize` option, `--merge-batch-size` or `VITEST_MERGE_BATCH_SIZE`. `0` turns batching off, and values below 2 are raised to 2. `runMergeReports()` takes the same `batchSize`, plus an optional `scratchDir`.
- The reduction uses the installed Vitest's own `flatted` and `@vitest/istanbul-lib-coverage` and writes the blob layout of Vitest 5.x. With another Vitest major, a blob in a different layout, or a batch that fails, the runner prints a warning and merges all blobs in one process as before.
- The reduced blobs live under the run's scratch directory and are removed on every exit path. `blobsDir` itself is never modified.
- `DEFAULT_MERGE_BATCH_SIZE` and `resolveMergeBatchSize()` are exported from the package.

Fixes [#129](https://github.com/CLDMV/vitest-runner/issues/129).

### Per-file coverage folders stay inside the run's scratch root ([#132](https://github.com/CLDMV/vitest-runner/pull/132))

The per-file coverage output used to go to a shared `<cwd>/.vitest-coverage-tmp`, so two runs in the same project could remove each other's folders. It now lives under each run's own scratch root, which a signal exit also cleans up.

## 🧪 Tests

- Each `run()` in the runner tests gets its own blobs folder, so test files running in parallel never clear each other's blobs ([#132](https://github.com/CLDMV/vitest-runner/pull/132)).
- Tests for the batched merge cover its fallbacks, its cleanup and the default paths, keeping coverage at 100% ([#132](https://github.com/CLDMV/vitest-runner/pull/132)).

## Upgrade notes

- No breaking changes. Suites with more than 50 blobs get the batched merge automatically; set `mergeBatchSize: 0` (or `VITEST_MERGE_BATCH_SIZE=0`) to keep the single merge.
- The package now ships a second helper script, `merge-batches-helper.mjs`, in `dist/` and `bin/`.
