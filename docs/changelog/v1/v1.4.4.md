# vitest-runner v1.4.4 Changelog

**Release Date**: September 2026
**Release Type**: Patch
**Branch**: `release/1.4.4`

---

## Overview

A small cleanup release: the `prepack` workaround from v1.4.0–v1.4.1 is no longer needed now that the underlying gap is fixed upstream, and the release-merge automation is re-synced to close a gap where an approval given before a slower check (CodeQL and similar) finished could leave a release PR stuck approved and green with nothing re-triggering the merge. No API changes.

---

## 🐛 Bug Fixes

### Dropped the `prepack` tsup-availability guard (#41)

v1.4.1 worked around `prepack` crashing CI's publish job (`sh: 1: tsup: not found`) with a heuristic that skipped rebuilding when `tsup` wasn't resolvable — the actual gap was upstream, in `CLDMV/.github`'s publish command not passing `--ignore-scripts` against the bare, already-built artifact directory it publishes from. That's now fixed in `CLDMV/.github` v4.29.1/v4.29.2 (`npm publish` no longer invokes lifecycle scripts there at all), and since this repo pins the rolling `@v4` tag, the fix was already live before this release shipped. `prepack` goes back to a plain `npm run build`.

---

## 🔧 CI & Tooling

### Re-armed the release-merge gate for every check-producing workflow (#49)

The release-merge automation re-evaluates whether the persistent `next → master` release PR can merge whenever a check on its head commit finishes — but it was only listening for `🧪 CI Tests & Build`. If an approval landed before a slower check (CodeQL is the common case) finished, the release PR could sit fully approved and green with nothing left to re-fire the merge check, requiring a manual `workflow_dispatch`. `release-merge.yml` is re-synced from the `CLDMV/.github` v4.29.2 template to listen for every workflow in the standard v4 set that can put a check on a release PR's head, scoped to `next`/`hotfixes` so feature-branch CI doesn't wake it unnecessarily.
